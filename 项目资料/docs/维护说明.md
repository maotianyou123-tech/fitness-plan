## 训练语义，不可混淆

常规12天：卧推A / 深蹲 / 休 / 卧推B / 硬拉引体 / 休 / 卧推C / 深蹲 / 休 / 卧推D / 硬拉引体 / 休。卧推依次4×9、5×7、6×5、7×3，下肢均5×5。每两轮常规后6天恢复；默认首次额外6天开局恢复。额外休息顺延。

常规每次12×25：6项各2组。单侧准备第一轮左25、第二轮右25，合计2组；交替动作每组合计25次。专项递增热身在循环之后且另外计算。练后辅助独立保存，不能混入12组。

恢复段卧推A参考2×5、卧推C参考2×3，用常规对应重量约80%；深蹲2×5、硬拉2×3用70%，向下取整，RPE≤6。恢复段取消12×25与全部辅助，不计加重。它是常规固定组次以外的明确例外。

六个主项的正常重量 `weights` 独立设置。TM只用作一次参考值填充（65/70/75/80%），不可据旧单次或RPE反推更高TM。整杆档距2.5/5kg；所有计划值向下对齐杠铃可装重量；杆重10/15/20可选。

正常上限卧推/深蹲8、硬拉7.5。正常未达标但做过工作组，结束当天并降低之后同类重量一档；只在保存时降一次，周期建议不得再对同一失败重复扣档。主项暂停不完成本日。准备后已疲劳会阻止加重。

进阶取最近两次同类、同重量、同组次的常规记录：全部达标且RPE≤7.5（2.5kg档）或≤7（5kg档），无准备疲劳，才建议加一档。周期结束、本人确认恢复后再应用；不自动每周加5kg。全部阈值和24＋6编排属于本版选择，不声称研究直接证明它们最优。

## 数据约定

存储键 `bench-rotation-v8`，version=8。结构：tm/increment/barWeight/weights、entryRecovery、phases、startDate、cursor、completed、records、notes、support、extraRest、archives、cycle。

- `sessionId` 只在一个周期内唯一（阶段ID＋索引）；归档保存完整周期快照，读取时不要把不同周期同名训练覆盖。
- `records` 保存所有尝试，包括暂停；`completed` 保存已结束主项的当时plan/actual/date/result，历史处方永远不按新设置重算。
- `support[sessionId].warmup/accessories[exerciseId]` 保存实际阻力、次数，warmup另有sets；保存主项后还能补填，最近对应record同步更新support快照。
- `actual.weights/reps/rpes` 是每组数组；未做组reps=0、rpe=null。`warmupTired` 独立于主项达标，用于抑制加重。
- 日期按本地中午计算避免UTC跨日；主项实际日期推动后续计划。卧推→下肢1天，下肢→卧推2天；extraRest另加1天；暂停同日训练重试至少延后2天。
- 正常结束和提前恢复都会把当前快照写入archives；提前恢复不能加重量。

旧存储键 `bench-smolov-v7`、`bench-personal-v6`、`bench-fenjue-v5`、`bench-rebuild-v4`、`bench-fen-jue-v3` 只读，不覆盖、不清理。初次进入v8可继承v7有效TM和器械参数，但不继承旧的冲刺负荷或训练进度。JSON导出包含这些旧数据和所有v8归档；当前未实现导入界面。
